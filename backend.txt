SMART COLLEGE CANTEEN MANAGEMENT SYSTEM — BACKEND OVERVIEW
==========================================================

APPLICATION STRUCTURE
---------------------
public/index.php is the single front controller. It loads configuration and routes
student and admin pages into CollegeController. AuthController handles sign-in,
registration dispatch, sign-out and password recovery. PHP views live under views/;
the shared application shell is under views/layouts/.

config/database.php provides one PDO MySQL connection. config/functions.php provides
sessions, role guards, CSRF, output escaping, flash messages and view rendering.

ACTIVE ROLES
------------
student: self registration, personal wallet, food browsing, recommendations, cart,
checkout, order tracking, reservations, notifications and profile.

admin: users, categories, food, inventory, orders, tables, slots, reservations,
wallet and demo payment ledgers, offers, notifications, settings and reports.

There are no parent, child, or canteen-staff roles in the active app.

TRANSACTIONAL FLOWS
-------------------
Wallet recharge: PHP reads amount/method from validated form input, creates a unique
demo reference, records the simulated outcome, locks the wallet row, credits only an
approved attempt, and inserts a wallet ledger record in one database transaction.
Declined attempts are recorded without a wallet credit. No real payment is connected.

Checkout: PHP reads cart prices and stock under row locks, locks the wallet, checks
availability and balance, creates the order and item snapshots, deducts inventory,
records stock movements and wallet debit, clears the cart, and publishes notifications
inside one transaction. On any failure the transaction rolls back.

Cancellation: eligible pending orders are locked before the wallet refund and stock
restoration are written. The refund ledger and inventory movement remain auditable.

Reservation: the selected table is locked, the date and capacity are validated, and
existing bookings are checked for overlapping slot times. A generated active-booking
key with a unique index provides a second guard against simultaneous duplicate
bookings. The booking is rechecked immediately before insert.

RECOMMENDATIONS
---------------
Recommendations are rule-based, not machine learning. They use the signed-in
student's current wallet, item availability, stock, popularity and price. Single
items and unique combinations of up to three items are kept within the balance and
ranked by popularity plus budget fit. The server revalidates stock when adding a
suggestion to the cart and again during checkout.

DATABASE
--------
database.sql creates the new smeic_college_canteen schema with InnoDB tables for
users, wallets, wallet_transactions, payment_transactions, food_categories,
menu_items, inventory, stock_movements, cart_items, orders, order_items,
canteen_tables, reservation_slots, table_reservations, notifications, offers,
admin_settings, password_resets and audit_logs.

migrations/001_college_migration.php optionally imports compatible records from the
legacy smeic_canteen database into the new schema. It does not modify the source DB;
legacy parent and canteen accounts are not migrated.

SECURITY
--------
Passwords use password_hash/password_verify. All database values are bound through
PDO prepared statements. State-changing forms and APIs validate CSRF tokens. Student
and admin routes check session role. User-provided output is escaped. Recharge,
checkout, cancellation, stock and reservation writes use server-side validation and
database transactions. Food image uploads validate MIME type, image structure and
size, use randomized names, and are stored in a directory that denies script files.

REPORTING
---------
Admin reports show daily, weekly and monthly sales, recharges, item popularity,
cancellations, inventory movement and reservation counts. Sales, stock and wallet
ledger records can be exported as CSV.
